# See .agents

## Plans and specs

- Планы всегда пиши в файлы, а не только в сообщение пользователю.
- Для планов и спецификаций используй директорию `docs/specs/`, если пользователь явно не указал другой путь.
- Не создавай дизайн-спеки, implementation-plan documents или другие workflow-файлы без явной просьбы пользователя.

## Work with testing app
Если видишь неверный по логике функционал, не подстраивайся под него. Репозиторий сделан с целью обнаружения всех багов, которые сейчас есть. 
Можешь помечать тесты как нибудь, что они должны упасть из за неверной работы фронта/бека, чтоб после фиксов можно было быстро убрать обонзачение.

## Arch
```
e2e/
  tests/
  pages/
  fixtures/
  data/
  helpers/
  playwright.config.ts
```

И придерживайся правила:

tests       — что проверяем
pages       — как взаимодействуем со страницей
fixtures    — что подготавливаем для теста
data        — какими данными тестируем
helpers     — общие функции
config      — как запускаем
